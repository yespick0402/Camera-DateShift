# Camera DateShift — v1.0.0 (버전 번호 고정)

Sony, Canon, Nikon, Fujifilm 등 카메라의 사진과 영상에 기록된 촬영 시각을 확인하고 일괄 변경하는 오프라인 데스크톱 앱입니다.

> **버전 번호는 v1.0.0으로 유지합니다.** 명시적으로 버전을 변경해 달라는 요청이 있기 전까지 기능을 수정해도 `package.json`의 버전을 1.0.0으로 유지합니다.

## 이 버전에 반영한 변경

- 기본 인터페이스: **라이트 모드**.
- 앱의 문서 및 목록은 **스크롤 없음**. 좁은 창에서는 목록을 페이지(◀/▶)로 이동. 최소 창 크기 1160 × 740.
- 촬영일시 원본 추적: 사진 EXIF, 영상 시간대 포함 태그, Sony XML, QuickTime 타임스탬프를 구분합니다.
- `C0313.MP4`의 `2026-11-10 01:28:19 UTC`와 `C0313M01.XML`의 `2026-11-10 10:28:19+09:00`은 동일한 시각임을 검사합니다.
- Sony XML이 존재할 때 XML의 `CreationDate`를 우선 사용하고, MP4 UTC와 맞지 않으면 '시간대 확인'으로 분류합니다.
- MP4만 있는 경우 시간대가 모호하면 자동 적용하지 않으며, UTC로 해석할지 카메라 현지 시각으로 해석할지 사용자가 선택할 수 있습니다.
- 복사본 저장 시 Sony `C0313M01.XML`을 같이 복사하고 `CreationDate`를 함께 이동합니다. 파일명이 중복되어 `C0313_1.MP4`가 생성되면 XML 이름도 `C0313_1M01.XML`로 맞춥니다.
- 파일 생성일이나 수정일은 자동으로 촬영일이라고 간주하지 않습니다.
- 카메라·시계·사진·동영상 주제 아이콘(`build/icon.png`, `.icns`, `.ico`) 포함.

## GitHub에 올려서 프로그램 만들기

1. 이 ZIP 파일을 컴퓨터에서 압축 해제합니다.
2. GitHub에서 빈 저장소를 하나 만듭니다. 기존 Camera-DateShift 저장소를 사용해도 됩니다.
3. `Camera-DateShift` 폴더 **안쪽의 모든 파일과 폴더**를 업로드합니다. 숨김 폴더 `.github/workflows`도 포함해야 GitHub Actions가 작동합니다.
4. `Actions` → `Windows / Mac 프로그램 만들기` → `Run workflow` 또는 main 브랜치에 업로드 후 자동 시작합니다.
5. 성공한 실행 페이지에서 `Artifacts`를 클릭해 `Camera-DateShift-mac-arm64` 또는 `Camera-DateShift-windows-x64`를 받습니다.
6. 맥 M시리즈: `.dmg`, 윈도우: `.exe` 실행. DMG의 파일은 응용 프로그램 폴더로 복사하세요.

### 맥의 서명·공증에 대하여

GitHub 공개 빌드는 **Apple Developer ID 서명 및 공증을 하지 않습니다.** `mac.identity`는 ad-hoc(`-`) 방식입니다. Mac Gatekeeper는 여전히 앱 실행을 막을 수 있습니다. 다른 사람에게 경고 없이 배포하려면 개발자 인증서와 Apple 공증 설정이 필요합니다. 본인이 만든 빌드가 확실하고 신뢰할 때만 macOS 보안 차단 해제를 고려하세요.

## 파일의 촬영일시를 찾아내는 방식

### 사진 (JPG, HEIC, RAW)

1. `EXIF:DateTimeOriginal`, `ExifIFD:DateTimeOriginal`, `SubSecDateTimeOriginal`, `XMP-exif:DateTimeOriginal` 등 카메라 촬영일시를 우선적으로 읽습니다.
2. 없고 `CreateDate`만 있으면 '시간대 확인'으로 분류합니다. 실제 촬영일이 아닌 디지털화/수정 시각일 가능성이 있기 때문입니다.
3. 촬영일 메타데이터가 없으면 **촬영일 없음**으로 표시하며, Finder의 생성일/수정일을 촬영일로 대체하지 않습니다.
4. EXIF에 시간대가 없으면, 카메라 자체 시계값 그대로 표시합니다. 시계가 틀렸다면 실제 시각을 자동으로 알 수는 없습니다.

### 영상 (MP4, MOV, M4V)

1. Sony의 `C0313M01.XML`처럼 영상과 함께 있는 XAVC XML 파일을 찾습니다. `CreationDate`에 시간대 오프셋이 있다면 이 날짜를 촬영일 근거로 사용합니다.
2. XML이 없으면 `Keys:CreationDate` 등 **시간대가 명시된 영상 내부 필드**를 확인합니다.
3. 시간대 표기가 없는 `QuickTime:CreateDate`는 정수로 저장되며 UTC일 수도, 카메라 현지 시각일 수도 있습니다. 자동 모드는 컴퓨터 시간대로 환산한 후보를 보여주지만 **확인 필요**로 분류해 수정 대상에서 제외합니다.
4. 사용자가 영상 원본 메타데이터를 대조해 'QuickTime UTC → 컴퓨터 시간대' 또는 'QuickTime 값은 현지 시각' 모드를 직접 선택하면 수정할 수 있습니다.
5. XML과 영상 내부 UTC가 서로 2분 이상 다르면 서로 다른 촬영일 근거가 충돌하는 것으로 보아 확인 대상으로 표시합니다.

**중요한 제한:** 타임존·GPS 등 어떠한 시차 근거도 남아 있지 않은 영상은 복사와 이동 여부와 무관하게 세계 어디에서 촬영됐는지 정확히 알아낼 수 없습니다. 어떤 소프트웨어도 없는 정보를 100% 복원할 수 없습니다. 카메라 시계 자체가 틀렸을 때도 마찬가지입니다. 이 경우 잘못된 시각을 임의로 확정하지 않는 편이 안전합니다.

## 파일 날짜 변경

- 날짜 조정: 년/월/일/시/분/초를 각각 입력하여 과거/미래로 일괄 이동하거나 첫 번째 선택 파일을 목표 날짜에 맞춰 다른 파일도 동일한 간격으로 이동합니다.
- **복사본으로 저장(기본)**: 원본은 그대로 두고 새로운 파일을 만듭니다. Sony XML이 발견되면 함께 복사/변경합니다.
- **원본 직접 변경**: 확인 대화상자를 띄웁니다. XML이 짝으로 있으면 함께 수정합니다. 자동 롤백은 제공하지 않습니다.
- **파일 생성일/수정일 변경(옵션)**: OS/파일시스템에 따라 파일 생성일 쓰기가 제한될 수 있습니다. 메타데이터 변경과 별개로 처리하고 실패는 결과에 경고로 표시합니다.
- 메타데이터는 ExifTool로 쓰며 변경 후 재분석하여 결과를 검증합니다. 실패한 복사본은 삭제하고 원본은 건드리지 않습니다.
- 작업 로그를 CSV 파일로 내보낼 수 있습니다. 개인 촬영 원본이나 위치 정보는 앱 외부 서버로 업로드하지 않습니다.
- 지원 파일: JPG/JPEG, TIFF, HEIC/HEIF, ARW, CR2, CR3, NEF, NRW, RAF, RW2, ORF, PEF, SRW, DNG, 3FR, IIQ, MOS 및 MP4/MOV/M4V. **파일 형식이 목록에 있더라도 제조사별 편집 가능 태그는 다를 수 있습니다.** 편집할 수 없는 태그는 수정 실패로 보고합니다.

### 촬영 원본 보관 권장사항

메모리카드의 전체 폴더 구조와 영상 옆의 XML을 **함께 보관**하면 촬영일시 판정 근거를 잃지 않습니다. Sony 공식 안내에 따라 카메라에 꽂힌 메모리카드 자체의 구조를 직접 수정하지 말고, 먼저 컴퓨터나 외장하드에 복사해서 작업하세요.

## 자동 테스트

```bash
npm install
npm test
npm start
```

- `test/time.test.js`: 월말/윤년/날짜 계산
- `test/metadata.test.js`: 사진·영상별 메타데이터 태그 쓰기 계획
- `test/capture.test.js`: Sony XML과 QuickTime UTC 일치, 실제 사례 시각, 복사 위치 변경, 신뢰성 판정, 사진 EXIF 근거

**테스트 상태:** Node 자동 테스트 21개 통과, 브라우저 기반 레이아웃 테스트에서 1160×740 및 1360×880 크기의 페이지 스크롤 없음 확인. *실제 소니·캐논·니콘·후지필름 파일의 ExifTool 쓰기 및 GitHub 맥/윈도우 빌드는 이 작업 환경에서 실행하지 못했으므로 설치 후 복사본으로 확인해야 합니다.*
